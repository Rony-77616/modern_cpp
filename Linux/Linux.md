# 3.进程和PID
ps命令：

进程可以理解为一个正在运行的程序实例。每个进程都有一个编号，叫做PID（进程ID）。同一个程序运行多次，可以产生多个进程，各自有自己的PID。

在ubuntu输入：
```bash
ps
```
它默认显示与当前用户、当前终端关联的一部分进程。

与用户关联的进程：Linux会记录每个进程以哪个用户身份运行。例如，直接启动的普通程序通常以rony身份运行，系统服务可能以root等其他身份运行。不带参数的ps通常默认筛选：运行身份与我相同的进程。


终端： 终端就是一个让我通过“输入文字、查看文字结果”来操作电脑的交互界面，负责接收我输入的内容，显示最后的结果。   Bash:命令解释器，负责理解并执行这条命令。

bash：bash的作用是理解并执行我输入的命令。与编译器在某种角度有点类似。


输入命令 ->  Bash理解并执行 -> 终端显示结果

关联的终端： Linux会给终端一个名称，例如dev/pts/0等。
关联，就是这个进程被哪个终端控制，就是这个进程与这个终端关联。  一个终端可以关联也就是控制多个进程，为了区分当前指令是给哪个线程使用，需要系统通过区分前台进程组来决定。Bash是一个程序，运行起来是一个进程。



常见输出：
|列名|含义|
|:---|:---|
|PID|进程编号|
|TTY|关联的终端|
|TIME|累计使用cpu的时间|
|CMD|程序名称或命令|

输入ps后，执行起来，ps也是一个进程，因为ps本身就是一个程序，执行它，会产生一个运行中的实例，也就是进程。但是并非每条命令都会创建一个新进程，例如cd由bash自己完成。

# 10.进程线程：fork()
之前学习的std::thread(),是创建线程，fork()是创建一个新的进程。在Linux的c++中，可以这样调用：
```cpp
   pid_t result = fork();
```
pid_t是Linux中用于表示进程编号的整数类型。

调用前，只有原来的进程。创建成功后，就有：
- 父进程：原来的进程
- 子进程：新创建的进程。
  
获取进程pid：
- 当前进程的pid：getpid()
- 当前进程的父进程的pid：getppid()

调用getpid：
|当前进程|getpid()|getppid()|result|
|:---|:---|:---|:---|
|父进程|父进程自己的pid|父进程的父进程的pid|子进程的pid|
|子进程|子进程自己的pid|父进程的pid|0|

创建子进程后，父进程内的result > 0;子进程内的result == 0；


fork创建了子进程之后，子进程运行的仍然是同一个程序，但他有自己的执行过程和内存空间。fork()成功后，父进程和子进程都变成可以运行的程序，系统会分别调用他们。执行过程可以理解成：
```bash
fork()之前：只有一个进程

fork()成功后：
父进程：从fork()返回值大于0的位置继续
子进程：从fork()返回值等于0的位置继续

pid_t result = fork();

if (result > 0) {
    std::cout << "父进程\n";
}

if (result == 0) {
    std::cout << "子进程\n";
}

父进程和子进程会各自执行对应的if，但谁先输出不确定。
在单核cpu上，通常是轮流获得cpu时间，在多核cpu上，可能真的同时运行。
如果父进程希望等子进程结束，需要显示调用：
waitpid(result,nullptr,0);
```

  注意：子进程会从这次fork()返回之后继续执行，不会重新从main()第一行开始执行。父进程也会继续往下执行。
   



父进程如何等待子进程结束：

fork()后，父子进程可以同时运行，父进程如果需要等待子进程完成，就调用：
```cpp
#include<sys/wait.h>
int status;
waitpid(result,&status,0);
```
这里：
- result：父进程中用来保存的子进程pid
- &status：用于接收子进程的结束信息
- 0：表示如果子进程还没结束，父进程就阻塞等待


waitpid还有一个作用，就是回收子进程资源，避免子进程变成僵尸进程。子进程退出后，父进程可以这样判断它是否正常输出：
```cpp
if(WIFEXITED(status)/*子进程是否正常退出*/){
   int code = WEXITSTATUS(STATUS);//获取子进程的退出码。
}
```


waitpid阻塞父进程，if(WIFEXITED(status))检查子进程是否退出。


注意：上述代码中的status是以int status；定义在父进程中的，为什么这样他就可以接收子进程的结束信息呢？因为在父进程的waitpid中，我们用
```cpp
waitpid(result,&status,0);
```
接收了status，并且是引用传递，他会在子进程结束之后，把子进程的结束信息写入这个地址，这个结束信息不一定是退出码本身，所以后面需要WIFEXITED(status)以及WEXITSTATUS(status)来解析。也就是总的来说，waitpid本身负责等待和填写状态，WIFEXITED(status)负责解析这个状态。





# 11.信号（signal）
信号是Linux发送给进程的一种通知，可以让进程：
- 结束
- 暂停
- 继续执行
- 执行某种特殊处理
他和退出码不同：退出码是进程结束后留下的结果，信号是通知进程发生了某件事。

## SIGINT:中断
在Ubuntu终端执行sleep 300，按ctrl+c，终端向前台进程发送SIGINT，sleep结束。SIGINT常见产生方式是ctrl+c，含义是终端前台程序

## SIGTERM：请求进程终止
通常通过kill命令发送。 kill -TERM 进程pid。

SIGINT和SIGTERM有什么区别：
- SIGINT和SIGTERM默认都可以让进程结束，但他们表达的意图不同
- SIGINT，终端会把信号发给前台进程组，表示当前想中断正在运行的程序。
- SIGTERM，请求程序结束运行，程序可以先保存数据、释放资源，再退出。

## c++中的信号接收以及处理

c++可以使用<csignal>中的std::signal注册处理函数，signal用来指定程序收到某种信号时，要执行哪个函数
```cpp
std::signal(SIGNAL,handler);//SIGNAL表示要指定处理哪种信号，handler表示指定收到信号后，执行哪个函数。
std::signal(SIGTERM,handler);
```

当程序收到信号时，系统会调用：
```cpp
void handler(int signal_number);//上面两种信号可以交给一个函数处理。handler就是收到信号后，要执行的函数
```
 
但信号处理函数里应该只做很简单的事情，例如设置一个标志：
```cpp
volatile std::sig_atomic_t stop = 0;

void handler(int handler_number){
   stop = 1;

   //int handler_number:接收信号编号。函数被调用时，会通过这个参数告诉我收到了哪种信号，例如SIGINT或者SIGTERM。
   
   //stop = 1：表示把退出标记改为1.这句话本身不会结束程序操作，需要主程序检查stop，发现改为1，结束循环。
   
   //stop的声明volatile std::sig_atomic_t：这个声明适合在这里用作信号处理函数与正常代码之间的简单标记。volatile要求程序真正读取这个变量的值，不能一直沿用之前读取的旧值。初始值0表示当前没有收到退出请求。

   //不要在处理函数中直接使用cout，也不要复杂操作。
   //正确的是信号处理函数：只设置stop
   //主循环：发现stop后，正常清理并退出。
   //这个函数相当于是为信号定义了一个处理函数。
}
```
执行顺序。
程序登记 handler->
主循环持续运行，stop 为 0->
你按下 Ctrl+C->
程序收到 SIGINT，执行 handler->
handler 把 stop 改为 1，然后返回->
程序恢复被打断的执行流程->
主循环下一次检查 stop发现它为 1->
退出循环，执行收尾代码，正常结束。


注意：
- 处理函数和stop的定义要写在全局作用域上，因为函数定义 要在全局变量，并且stop的修改，要让处理函数handler知道stop是谁，因此stop要定义在全局变量中，并且在handler之前。而signal定义就要写在main函数开始，因为他是一句函数调用语句，告诉程序运行到这里时，登记信号处理规则。
- stop的类型不能是简单的int。原因是std::sig_atomic_t
  类型是为这种信号处理场景提供的简单标记写法。即使没有创建其他线程（也就是c++程序内部不需要再创建一个线程），信号也可以在主流程执行到任意位置时到来，让程序临时执行handle()。 
- volatile告诉编译器这个代码的值可能在当前代码之外突然发生变化，每次使用的时候都需重新读取。
- 为什么handler处理函数内不能直接使用std::cout、锁、或者容器操作，而是只改标记。因为：可能这些操作该时刻可能正在被主流程使用，内部可能持有锁或者正处于中间状态，处理函数再次访问就有可能导致死锁、输出混乱、内部状态损坏、程序崩溃。


为什么发出这两个让程序终止的信号，只是中断了循环，没有直接让程序终止？
- 因为注册了自定义处理函数，改变了这两个信号的默认行为。如果没有自定义处理函数，就会退出。


# 12.文件描述符
文件描述符是一个由Linux分配给进程的整数，用来代表一个已经打开的资源。这个资源可以是普通文件、终端、管道、网络连接、设备。所以它不只是文件，而是可以进行输入输出的对象。

每个进程启动时通常已经拥有三个文件描述符：
|数字|名称|用途|
|:---|:---|:---|
|0|标准输入stdin|读取键盘输入|
|1|标准输出stdout|输出正常信息|
|2|标准错误stderr|输出错误信息|

例如：
- std::cout<<"hello";通常会写入文件描述符1（把数据写到编号为1的输出管道）

- std::cin>>x;会从文件描述符0读取（从编号为0的输入管道中读取数据）

所以可以把文件描述符0、1、2理解为进程中的三个通道编号。通道连接到终端时，就是从终端输入或者从终端看到输出，连接到文件时，数据就来自文件或者写入文件。其中，Linux会为每个进程维护一张表，可以想象成一个文件描述符表，编号就指向这个资源。当执行特定操作时，Linux会根据文件描述符表查表。获取资源。所以文件描述符本质上就是一个整数，通过它可以获取想要的资源，所以通俗叫做一个通道。也就是说012是默认连接到终端，使用cincout等在终端输入输出，就是先去文件描述符表找到012连接的那个资源（也就是终端），然后这个时候cincout也就知道它的输入输出在终端。


文件描述符本身只是一个整数，数字3可能代表某个打开的文件，数字4可能代表一个网络环境。



## open
open是Linux提供的函数，用来打开文件或者其他输入输出资源。他返回一个文件描述符。
```cpp
int fd = opern("data.txt",O_WRONLY| O_CREAT,0644);
```
其中参数：
- "data.txt":要打开的文件路径（相对、绝对都可以）
- O_WRONLY:只写
- O_CREAT：文件不存在时创建
- 0644：创建文件时设置的权限（八进制数，开头0表示是一个八进制数字。权重：读 r = 4，写 w = 2，执行 x = 1，后面数字是这些权重加起来，有哪些权限就加多少，第一个是所有者权限，第二个是同组权限，第三个是其他用户的权限）。
- |：按位或，用来组合多个选项。

open常见写法：int fd = open("data.txt",打开选项)；
- 如果需要创建文件，还要加第三个参数：("data.txt",打开选项，权限);

也就是可以理解成：open(路径，打开方式，新文件权限);

| 选项 | 含义 |
|---|---|
| `O_RDONLY` | 只读 |
| `O_WRONLY` | 只写 |
| `O_RDWR` | 读写 |
| `O_CREAT` | 文件不存在时创建 |
| `O_TRUNC` | 打开时清空原有内容 |
| `O_APPEND` | 写入时追加到文件末尾 |
| `O_EXCL` | 配合 `O_CREAT` 使用，文件已存在时失败 |

前三个是访问方式，通常只能选一个。其他选项可以组合|使用。


返回值：fd >= 0 打开成功，fd就是文件描述符。fd == -1打开失败。

## write
通过文件描述符，把数据写进对应的资源。在要进行写操作时，打开的文件必须是允许写入的打开方式。如果是只读，使用write会失败，不会写入数字，write会返回-1，所以一般需要检查。

用法：
```
write(文件描述符，数据所在位置，要写入的字节数);

ssize_t n = write(fd,"hello\n",6);
```
参数：
- fd指定写入哪个已经打开的资源，这里是data.txt
- "hello\n",要写入的数据，实际上第二个参数要的是写入的数据在程序内存中的位置。
- 6，请求写入6个字节：五个字母加一个换行符
- n：保存实际写入的字节数，write会返回实际写入的字节数
- ssize_t：可以保存字节数。


注意：
- 一次write不一定可以保证能写完所有请求的数据，若返回值小于请求的字节数，说明只写入了一部分。
- 使用cerr来输出错误信息，而不用cout，是为了方便把错误信息和正常结果分开。一般没有区别，假如有一个重定向了之后，就有区别了。cout重定向到文件之后，cout的内容会写入重定向指向的文件，cerr就还是在终端显示错误信息。但是如果想错误了只需打印错误信息，而没有错误就把输出写入文件，就需要条件判断。
- ssize_t是一个有符号整数类型，因为write返回的本来就是ssize_t，使用相同类型接收，避免不必要的转换开支。



怎么知道write的第三个参数要写入多少个字节？
当我们遇到一个很长的文本的时候，就需要快速得到长度。

- 可以使用字符数组，让程序计算长度：
```
char text[] = "hello\n";
sizeof(text)- 1; 因为数组末尾会有\0，要去掉，如果不用sizeof - 1，就有可能多读取，如果没有定义，就会报错或者读取相邻内存里的未定义的字符。
```


## read
从文件描述符对应的资源中读取数据，放进程序的内存。

基本用法
```
read(文件描述符，存放数据的位置，最多读取多少字节);

char buffer[100];
ssize_t n = read(fd,buffer,sizeof(buffer));
```

解释：
- char buffer [100] 是定义了一个能放100字节的字符数组，作为接收数据的缓冲区。
- read返回 >0,成功读取到n个字节。= 0 ，对于普通文件，表示已经读到文件末尾，没有数据可读，一个字节都没读到 。 = -1 读取失败。 
- 连续使用同一个fd读取时，会从上一次读到的位置继续，不会每次从头开始读。
- 实际读了多少字节，就请求写入多少字节，不能一律写sizeof(buffer)，否则可能把没有读到有效数据的部分也写进buffer。第三个参数表示这次最多允许读取多少字节，假如buffer空间比读取的文件大，那读取buffer空间那么大的字节数，文件有多少个字节，就读取多少个字节，返回的是文件的字节数
- read不会自动给数据添加字符串结束符 '\0'，因此暂时不要直接用 cout << buffer 输出数组内容。

注意，如果一个文件操作完，不会回到开头位置读取，会在上一个操作完的位置开始读取，如果想从文件开头读取，可以在 read 前调用：lseek(fd, 0, SEEK_SET);




## lseek
它用来调整文件的读写位置。

一个文件描述符通常会记录当前读写位置，例如：
```
打开文件：位置0 -> write写入10个字节：位置变成0->read：从10位置继续读取。
```
所以写入后直接读取，通常不会从文件开头读取。

lseek的基本格式：
```cpp
lseek(文件描述符,偏移量，参照位置)
```
参数：
- 文件描述符表示操作哪个文件的读写位置
- 偏移量：要移动多少字节（正往后移动，负往前移动）
- 参照位置：从哪里开始移动
| 参数 | 含义 |
|---|---|
| `SEEK_SET` | 以文件开头为参照 |
| `SEEK_CUR` | 以当前位置为参照 |
| `SEEK_END` | 以文件末尾（最后一个字节）为参照 |


假如移动的超过文件字节数，移动位置本身不会失败，就是移动到指定位置，中间是空洞（表现为0字节，这种文件有时候叫稀疏文件）。假如移动位置在开头之前，就会失败，返回-1，如果没有失败返回当前位置。

普通文件的 read 和 write 会根据实际成功传输的字节数自动推进读写位置。


## 阻塞非阻塞
读取写入操作都会存在阻塞与非阻塞

阻塞：某个操作暂时无法完成时，调用它的线程停下来等待，满足条件后再继续。

例如从终端读取，没有输入时，线程停在read里等待。当写入时，数据通常需要先放进系统的缓冲区，如果缓冲区已经满了，写入操作就可能等待空间腾出来。


非阻塞：没有数据可读的时候，立即返回，让程序有机会继续做其他事情。

例如当终端没有数据可读的时候，立即返回。


## 13.perror
让程序输出具体失败的原因。`#include<cstido>`

之前使用的cerr只能知道是失败了，但是不能知道是为什么失败。

```cpp
if(fd == -1){
   std::perror("打开文件失败");
   return 1;
}
```
perror会读取当前的errno，把错误码转成文字，输出到错误列表。

例如输出：打开文件失败：NO Such file or directory

只有一个参数，就是我想加在错误信息前面的文字。

注意：
- 在操作返回失败后，即使调用perror，避免其他操作改变errno
- 他输出标准错误，在linux中通常对应描述符2
- 他只负责打印，不会结束程序。
