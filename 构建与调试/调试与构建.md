前面学习了编译信息的两个另外的补充：
- -O2编译优化关闭：若开启编译优化，就可能编译的时候会有某些代码进行合并，但编译结果可能和源码对应不上，调试难度会大一些。假如关闭了，调试会比较方便，但是程序运行的效率可能降低。因此，尽量在调试的时候-O0关闭编译优化，在真正运行的时候开启编译优化
- -g：若不写，valgrind信息显示里面可能没有定位到哪一行的内存泄露，可能只会有函数名或者地址，不方便定位。

# 1.补充g++的编译警告

在编译命令里加两个选项：
```bash
g++ -std=c++20 -g -O0 -Wall -Wextra test.cpp -o test
```
新增选项作用：
- -Wall:开启一组常用警告
- -Wextra：再开启一些额外警告



# 2.CMake
CMake是用配置文件管理c++的编译。

之前每次都输入指令编译，但是当程序有很多源文件、很多编译选项的时候，每次手写命令就比较麻烦。CMake可以把这些编译要求记录下来，方便重复构建。但是真正编译c++代码的，仍然是g++等编译器。

代码在Linux内cpp_practice内的cmake_practice文件夹下。

在要编译的文件的同一个目录中，创建一个配置文件，名称必须是：CMakeLists.txt

写入：
```
cmake_minimum_required(VERSION 3.16)

project(HELLOPractice LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 20)

add_executable(test cmake_practice.cpp)
```
解释：
- ```camke_minimum_required(VERSION 3.16)```:指定至少需要CMake 3.16
- ```project(HELLOPractice LANGUAGES CXX)```:
项目名为HELLOPractice，使用c++。（这个项目名称是给整个项目起的名字，cmake会记录他，供后续配置、开发工具显示项目信息等使用）。
- ```set(CMAKE_CXX_STANDARD 20)```:把使用的c++标准设置为c++20
- ```add_executable(test cmake_practice.cpp)```:用cmake_practice.cpp构建一个名为test的可执行程序。这里要编译的文件的位置，以当前CMakeLists的目录位置为起点，去写要编译的文件的位置。

然后，生成构建配置。在cmake的终端下，执行：
```
cmake -S . -B build    //`build` 的具体位置由 -B 后面的路径决定
```
解释：
- -S .：源代码和CMakeLists.txt在当前目录
- -B build：把生成的构建文件放进build目录；不存在时自动创建build，若cmakelists.txt在当前终端的上一级目录中，就要-S.. -B../build，表示到上一级目录寻找cmakelists，在上一级目录中创建build（build一般和cmakelists写在一个目录）。
- 也就是说，-S后面的路径，是以当前终端的路径为起点，找CMakeLists的路径。然后后面-B生成的build文件，也可以指定位置，或者写在自己想要的位置里面。

这一步生成构建配置，还没有编译cpp_practice.cpp


最后，编译并运行。执行：
```
cmake --build build
```
意思是按照build中的配置进行编译。成功后，再运行：
```
./build/test
```

就是全部的编译流程。以后修改了源码之后，通常只需要cmake --build build重新编译，然后再./build/test运行。到上一级编译cmake --build ../build(路径自己灵活写)。


注意：
- 假如源代码不再同一个目录下，就把需要的文件的路径或绝对路径都写在executable里面。
- 给cmake加上编译警告信息。再加一行：
  ```bash
  target_compile_options(test PRIVATE -Wall -Wextra)
  ```
  其中：
  - target_compile_options:给制定目标添加编译选项
  - test：要设置的目标，就是前面创建的程序
  - PRIVATE:这些选项用于编译该目标自身
  - -Wall -Wextra 开启常见警告和额外警告





# 3.构建一个方便调试的程序
在项目目录执行：
```
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
```
这里：
- -D：设置一个CMake配置变量
- CMAKE_BUILD_TYPE:变量名称，表示构建类型
- Debug：变量的值，选择调试构建

这样就是用Debug构建，会自动加入-g，并且不启用优化编译，适合调试。相当于前面编译指令的 -g -O0。若不构建debug，仍然可以编译、运行，也可以用 GDB 启动程序，但通常无法方便地按源码行调试、查看局部变量。

# 4.GDB
在项目目录执行：
```
gdb ./build/test
```
用gdb加载刚刚构建的test程序，准备调试。此时程序还没开始运行。

看到(gdb)说明已经进入gdb。接下来的命令是在这个提示符后输入。

## 设置断点
断点就是：程序进行到这里时，先暂停，等我下一步操作。但是断点打在第四行，是第四行还没执行，执行到第三行就暂停。
break main（可以用行来指定，cpp_practice:4,第四行打断点）
- break：设置断点
- main：指定断点位置,即进入main函数的第一行，main()后的第一行

## 启动程序
run，程序开始运行，进入main后会在断点处暂停。


## 继续执行
continue，让程序从断点处继续执行。没有其他断点时，会一直运行到结束。

## 退出gdb
quit

## 查看变量
print 变量名。

## next和step
执行next指令会控制已经暂停的程序，让他执行完当前断点那一行，并且往下一行打上断点。
step也是这个作用，但是他们的区别在于，遇到当前已经打上断点那一行有函数调用时：
- step会进入函数第一行打上断点。
- next会执行完函数，得到返回值，在主函数里的下一行打上断点。


## finish
进入函数后，让这个函数执行到返回，再暂停。也就是函数返回后，再暂停，有可能回到main后，GDB可能仍然显示调用函数的这一行，因为函数已经返回和这一整行已经执行完成中间可能有步骤差，暂停位置可能在这一行的执行中途。如果还在同一行，可以输入next。





## 查看所有断点
输入：
```
info breakpoints
```

## 删除指定断点
查看断点后，根据显示的断点编号（Num），执行：
```
delete 1
```
如果当前程序正暂停，删除断点后，程序仍然停留在那里，删除设置不会自动继续执行。


## backtrace
查看程序经过哪些函数调用，到达当前暂停位置的。
显示的编号从当前函数开始，向调用它的外层函数排列。
这个函数的实际用用途是：当程序在某个函数里面出错或暂停的时候，不仅能知道现在在哪，还能知道是谁调用它，怎么来到这里。

      
## gdb调用栈帧和查看变量

前面backtrace显示的#0、#1 叫做栈帧编号。每个正在执行、但还没有返回的函数，都有一个栈帧，里面记录着：函数参数、局部变量、返回位置。

- 查看当前栈帧
```
frame
```
作用是显示当前正在查看的栈帧。通常当前函数是#0。

若要选择指定栈帧，输入：
```
frame 1
```


- 显示变量：
```
info locals
```
作用是显示当前选中函数的局部变量。

查看当前函数的参数：
```
frame 0
```
然后输入：
```
info args
```
显示当前函数收到的参数。

- 切换选中函数
```
up
```
向调用者方向移动一层

```
down
```
向当前函数内部方向移动一层

注意：所有函数都是一层套一层，没有同时调用的，因为这一条调用完才会执行main中的下一条，所以不会出现main中调用的两个不同函数谁在前谁在后的问题。



## gdb观察点
观察点就是当变量的值发生变化时自动暂停。
普通断点关注的是程序执行到某一行时暂停
而观察点关注的是某个变量的值发生变化时暂停。
在变量初始化后输入：
```
watch 变量名
```
然后观察的变量发生改变了，就会暂停，显示。

info watchpoints只会显示所有的观察点
info breakpoints会显示所有点，包括断点和观察点
watch到值改变后，一改变就暂停，有可能这一行还没执行完，就在这一行打断点。若这一行已经执行完，就在下一行打断点。



## 条件断点
也就是执行到指定位置，并且条件成立时，才暂停。
在进入gdb后输入
```
list main
```
它会显示main()附近的源码以及行号，不会运行程序，找到要打断点的行号，再写上要暂停的条件：
```
break gdb_practice.cpp:16 if i==5
```
程序会在i = 5的时候暂停，也就是只输出到01234就暂停。这种断点方式表达：程序在到达指定代码位置，并且满足条件时暂停。





## 用gdb找到程序错误位置

程序执行到错误位置时，gdb默认会暂停，并显示：
- 错误类型（信号）
- 当前错误位置(错误出在哪个函数、第几行)
- 对应的源码


注意：这种只能快速定位编译失败报错位置，不能显示内存泄露等问题




## display
每次程序暂停时，自动显示变量的值

```
display i
```
每次暂停都会显示变量i的值


```
info display
```
查看当前有哪些自动显示项

```
undisplay 1
```
删除编号为1的自动显示项

## disable和enable
disable暂时禁用断点，enable恢复断点使用。
```
disable 1
enable 1
```
