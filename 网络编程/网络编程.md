# 什么是网络编程
网络编程就是：让一个程序通过网络，和另一台电脑上的程序交换数据。

比如我用浏览器打开网页：
```
浏览器程序 <—— 网络 ——> 网站服务器程序。
```
浏览器先把请求发给服务器，服务器返回网页内容。这个过程就是网络编程的实际应用

1. 网络是什么？
网络就是让多台设备能够相互传递数据的连接，设备可以是电脑、手机、服务器、路由器等等，数据可以是文字、图片、视频或者程序之间交换的指令。

2. 程序之间怎么找到对方？
需要两个信息，分别是：ip地址和端口号

- ip地址可以理解为电脑的地址，例如：
```
192.168.1.20
```
    他可以回答：数据要送到哪台电脑。

- 端口号可以理解成电脑上的门牌号或者房间号，例如：
```
8080
```
    它可以回答：到达这台电脑后，要交给哪个程序。因为一个电脑可以同时运行很多个程序。


3. 客户端和服务器是什么？

客户端是发起请求的一方。例如：浏览器、手机app、聊天客户端

服务器是等待请求、处理请求的一方。例如：网站服务器、文件服务器、聊天服务器。

典型过程是：服务器处于等待连接状态，客户端发起连接请求，服务器收到请求，处理数据，服务器返回结果，客户端接收到结果

服务器通常需要一直运行，等待客户端连接；客户端一般由用户操作后发起请求。


4. 协议是什么？
协议就是双方提前约定好的通信规则。

例如双方要约定：
- 数据怎么开始
- 数据到哪里结束
- 每个字段代表什么
- 出错时怎么办
- 谁先发送、谁后发送

如果客户端和服务器使用不同规则，即使网络通信连接成功，也无法 正确理解对方的数据。和人说话的语言类似。

5. 数据为什么要分成小块
程序发送的数据可能很大，网络通信通常会把他分成许多小块传输，这些小块可以叫数据包。接收方再把他们处理成需要的内容。

这里就会有两个问题：
- 数据包可能被拆开
- 多条消息可能连在一起

后面会具体学习


6. TCP和UDP是什么？
TCP和UDP都是通信协议，也就是程序之间传输数据时可以采用的不同规则。

TCP可以理解成：
先建立连接，双方确认能够通信，按顺序传输数据。尽量保证数据到达，出错时可以重新传

UDP可以理解成：
不需要先建立连接，直接发送，可能丢失，可能乱序，速度快，额外开销小。

所以二者的区别使得其用途不同 ：
- TCP：可靠、有顺序，适合网页、文件、登录等 。
- UDP: 简单、快速，适合直播、游戏、DNS等。




# socket
1. socket介绍和用法
socket可以理解为：程序和网络之间的一个通信入口。

之前的文件描述符：
```cpp
int fd = open("data.txt");
```
open()返回的一个文件描述符，程序通过他读写文件。

网络中的socket也类似：
```cpp
int fd = socket(...);
```
socket()返回一个文件描述符，程序通过它读写网络数据。

区别是：普通文件描述符连接文件，socket文件描述符连接网络通信端点，而一个网络通信端点由这些信息确定：
- IP地址
- 端口
- 通信协议
  

所以，创建socket的函数形式是：
```cpp
int socket(int domain,int type,int protocol);
```
参数含义：
- domain：地址类型
  - AF_INET：使用IPv4
  - AF_INET6:使用IPv6
- type：通信方式
  - SOCK_STREAM:字节流，通常用于TCP
  - SOCK_DGRAM:数据报，通常用于UDP
- protocol：具体协议，通常写0，让系统根据前面的参数选择默认协议。

例如：
```cpp
int fd = socket(AF_INET,SOCK_STREAM,0);
```
创建一个使用IPv4，采用tcp风格通信的socket。

如果成功，返回一个非负文件描述符；失败返回-1，原因可以通过errno或者perror查看。

2. tcp服务器需要两个不同的socket
服务器的基本流程：
```
socket()——>bind()——>listen()——>accept()——>send()/recv()
```
他们的作用分别是：
- socket():创建网络通信入口
- bind()：给这个socket绑定本机ip和端口
- listen():让TCP socket进入等待连接状态
- accept()：接收一个客户链接
- send()\recv()：和这个客户交换数据
